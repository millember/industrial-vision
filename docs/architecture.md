# Архитектура Industrial Vision

## Реализовано на первом шаге

Python 3.12, FastAPI, Uvicorn и uv; зависимости — pyproject.toml + uv.lock. Точка входа — `backend/app/main.py`.
Единственный бизнес-независимый endpoint: `GET /api/v1/health`.
Swagger и OpenAPI генерирует FastAPI. БД, вход сотрудников, анализ снимков и уведомления ещё не реализованы.

```text
Браузер → HTTPS pet.oppennec.ru → существующий Traefik
  /industrial-vision/ → pet-web Apache → React-страница каталога
  /industrial-vision/api/... и docs/openapi.json
    → удаление префикса /industrial-vision
    → сеть proxy → industrial-vision-api:8000 → FastAPI
```

`compose.yaml` — локальная разработка: bind mount исходников, Uvicorn с reload, порт ноутбука.
`compose.server.yaml` — сервер: отдельный Compose-проект industrial-vision, без reload и bind mounts, без опубликованных портов хоста.
Контейнер работает от UID/GID 10001, с read-only корневой ФС; временные файлы допустимы в /tmp.
256 МиБ и 1 CPU — конфигурационные лимиты каркаса, не результат измерения модели.

Traefik использует существующие сеть proxy, вход websecure и resolver le. Маршруты соседних сервисов не заменяются.
TLS завершается на Traefik; Uvicorn слушает HTTP только внутри контейнерной сети.
Хостовый порт 443 и цепочка REALITY → Traefik сохраняются.

## Следующие шаги

SQLite, миграции и демонстрационные данные вводятся на шаге 2. Для БД и фотографий понадобятся постоянные volumes и доступные на запись каталоги; сейчас таких данных нет.

При появлении бизнес-логики HTTP-схемы и маршруты остаются на границе API, сценарии приложения управляют операциями, домен хранит правила, инфраструктура реализует БД/файлы/модель. Зависимости собираются явно.
Не создавать пустые слои вокруг health endpoint и не переносить бизнес-правила в маршрут.
