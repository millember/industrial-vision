# Сервер ↔ модель — контракт 1.0-draft

Предложение для Софии. Не утверждает, что модель уже реализована или поддерживает все классы.
Владелец модели — София; адаптера и бизнес-правил — Нияз.

## Вход адаптера

Нормализованное по EXIF изображение JPEG/PNG, его ширина и высота. Один снимок выбранного оборудования и один проверяемый узел. Если нужна зона ожидаемой установки, она задаётся конфигурацией макета, маркером или другим согласованным способом. Она не выводится из отсутствия детекции.

Как передать снимок конкретной модели — bytes, локальный путь или HTTP multipart — определяется после получения её реального интерфейса. Произвольный пользовательский путь/URL модель не получает. Авторизация, цех и серверные ID не входят в обязанности модели.

## Выход адаптера

Пример: [model-warning.json](examples/model-warning.json).

| Поле | Тип | Проверка |
|---|---|---|
| model_version | string | Непустой ID версии модели |
| image | object | width/height соответствуют нормализованному входу |
| observation | string | Один из кодов таблицы ниже |
| confidence | number/null | Конечное число [0, 1]; null только при UNDETERMINED |
| box | array/null | Четыре целых пиксельных значения нормализованного входа |
| reason | string/null | Причина неопределённости; обязательна при UNDETERMINED |
| expected_location_verified | boolean | Подтверждена ли ожидаемая видимая точка установки |

Это унифицированный выход серверного адаптера. Если настоящая модель отдаёт список детекций, иной набор имён или нормированные координаты, адаптер явно преобразует его. Софии не требуется переписывать модель под HTTP-схемы Android.

## Классы и серверный маппинг

| observation | Бизнес-код | status/color | Требование |
|---|---|---|---|
| FASTENER_SEATED | null | OK/GREEN | Установленный крепёж действительно виден и распознан |
| FASTENER_PROTRUSION | FASTENER_PROTRUSION | WARNING/ORANGE | Поддерживаемый признак неполного прилегания |
| FASTENER_MISSING | FASTENER_MISSING | CRITICAL/RED | Известная видимая точка установки, expected_location_verified=true |
| FASTENER_REMOVED | FASTENER_REMOVED | CRITICAL/RED | Поддерживаемый признак выкрученного крепежа и известное место установки |
| UNDETERMINED | null | UNKNOWN/GRAY | Недостаточно данных, неизвестный объект или плохое качество |

Для FASTENER_REMOVED также требуется expected_location_verified=true. Отдельно лежащий саморез не доказывает поломку выбранного агрегата. Для первых двух классов рамка обязательна; для MISSING/REMOVED нужна область установки. Для UNDETERMINED box=null.

Список — предлагаемая таксономия. Если модель различает только два состояния, остальные нельзя симулировать как реальное распознавание. Поддерживаемые классы и пороги согласуются на реальных изображениях.

Низкая уверенность известного наблюдения преобразуется сервером в UNKNOWN с объяснением. Порог — настройка, согласованная с Софией, без выдуманного значения по умолчанию. Неизвестный observation вне контракта — ошибка формата MODEL_INVALID_RESPONSE; модель должна явно сообщать UNDETERMINED для неподдерживаемого входа.

## Координаты и ошибки

Адаптер отменяет модельные resize, letterbox, нормирование и поворот. Его box всегда соответствует исходному нормализованному снимку. Если модель даёт дробные границы, адаптер берёт floor для левой/верхней и ceil для правой/нижней; не исправляет произвольные координаты за пределами изображения молча.

Проверки: конечные числа, известный класс, допустимая confidence, корректная рамка, совпадение размеров и обязательные условия известной точки установки. Некорректный ответ даёт 502 MODEL_INVALID_RESPONSE. Таймаут — 504 MODEL_TIMEOUT; недоступность сервиса — 503 MODEL_UNAVAILABLE. Ошибки не подменяются нормой или mock.

Рекомендацию и каталог дефектов задаёт сервер, а не свободный текст модели. Проверка специалистом независима от confidence. Физическая исправность всего агрегата не выводится из одного осмотренного крепления.

## Режим заглушки

Только явное включение mock при разработке. Android получает analysis_source=MOCK, model_version=null. При реальной модели — MODEL и её версия. При сбое реальной модели автоматического mock-fallback нет.

Mock-примеры для UI полезны для параллельной работы; они не являются свидетельством качества модели.

## Что нужно получить от Софии

1. Реальный интерфейс запуска и пример вызова.
2. Поддерживаемые классы и обозначения.
3. Весовой файл/адрес API и версию модели.
4. Преобразования изображения и координат.
5. Контрольные фотографии, включая неизвестный объект и плохой снимок.
6. Подтверждение способа определения отсутствия крепежа.
7. Порог confidence и показатели на контрольных данных.
8. Измеренные CPU/RAM/GPU, зависимости и время анализа.

## Критерий готовности интеграции

Настоящее фото проходит через адаптер; контрольное наблюдение и рамка проверены; ошибки и UNKNOWN различаются; исходная версия модели сохранена. Это критерий будущего шага подключения модели, а не результат создания контракта.
