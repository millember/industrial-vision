# Шаг 1 — каркас FastAPI и первый запуск

Продолжение [подготовки контрактов](01-contracts.md). В первом коммите были опубликованы документы; этот этап добавляет рабочий HTTP-каркас и серверный запуск.

## Объём

- Сохранить существующий health endpoint и формат ответа.
- Включить ранее подготовленные FastAPI/Docker-файлы в Git вместо шаблона PyCharm.
- Разделить локальную разработку и серверную конфигурацию.
- Добавить отдельный HTTPS-маршрут Industrial Vision.
- Не добавлять пока БД, авторизацию и распознавание.

## Наблюдаемые критерии готовности

| Критерий | Проверка |
|---|---|
| API стартует | GET /api/v1/health → HTTP 200 и JSON status=ok |
| Документация доступна | GET /docs → 200; OpenAPI содержит health маршрут |
| Серверный запуск без dev-режима | Нет reload, bind mount исходников и опубликованных host ports |
| Контейнер непривилегированный | Dockerfile задаёт USER 10001:10001 |
| Compose корректен | Локальная и серверная конфигурации проходят compose config |
| Публикация из коммита | Архив и manifest содержат только явный список файлов, REVISION равен хешу |
| Приложение доступно по HTTPS | Health и Swagger на pet.oppennec.ru/industrial-vision после активации |
| Соседние сервисы сохранены | Существующая главная по HTTPS продолжает отвечать |

Результаты отмечаются только после фактических проверок. Подготовленный маршрут сам по себе не означает, что контейнер запущен или сертификат выпущен.

## Публикация

Архив текущего коммита передаётся в отдельный каталог релиза `~/services/industrial-vision/releases/<commit>/`.
`release.env` содержит RELEASE_ID, а REVISION и SHA256SUMS связывают файлы с коммитом.
До запуска `pending` указывает на подготовленный релиз. После проверки контейнера и HTTPS `current` атомарно указывает на рабочий.
Указатель `current-docs` прежнего релиза документов независим от приложения.

Контейнер запускается в Compose-проекте industrial-vision. Команды Docker требуют sudo в терминале пользователя сервера.
Все публикации используют общую блокировку ~/services/.home-server-deploy-lock; чужую блокировку не удалять.
Маршрут сначала хранится вне Traefik dynamic и переносится туда только после готовности backend.

Первый запуск не заменяет существующий сервис Industrial Vision: до него опубликованы только документы.
До активации проверить отсутствие конфликтующего DNS-имени, router/service ID, network alias, образа/проекта и файла маршрута.
При ошибке первой активации убрать только новый маршрут и остановить только новый Compose-проект; оставить архив для диагностики.
При будущих обновлениях сохранять прежний релиз и проверять отсутствие drift перед откатом. Откат кода не означает откат будущих миграций БД.

## Проверено до первого запуска сервера

- uv lock --check и uv sync --locked: 21 разрешённый пакет, зависимости зафиксированы в backend/uv.lock.
- Обе Compose-конфигурации проходят config --quiet.
- Образ собран через uv 0.12.9; временный контейнер с UID 10001, read-only FS и cap-drop ALL прошёл health 200/JSON, Swagger 200 и OpenAPI с pet-префиксом.
- Штатный make frontend-test: 18 тестов и lint успешны. Сборки каталога выполнены штатным watcher, страница опубликована.
- Проверка страницы в браузере: правильные ссылки, отсутствие горизонтального переполнения на проверенном размере; недоступный API не отображается как успешный.

Серверный контейнер и публичные API/Swagger проверяются после привилегированного запуска; эти проверки пока не отмечены выполненными.

## Исправление прав при распаковке

Распаковка tar под umask 077 без сохранения архивных режимов дала backend/app=700 и Python-файлы=600. COPY в образ назначил им владельца root, и UID 10001 не смог импортировать app/__init__.py. Ошибка воспроизведена на исходном коммите 3d5554a: PermissionError, exit 1.

Для нового релиза сохранять исходные режимы: tar --no-same-owner --same-permissions -xf release.tar. Корневой каталог релиза остаётся закрытым. Для текущего релиза режимы backend восстановлены строго из проверенного архива, владелец и содержимое не менялись, SHA-256 совпадают. Повторная локальная сборка из распакованного контекста прошла health 200/ok при UID 10001 и read-only/cap-drop. После повторного запуска короткой командой start серверный контейнер стал Healthy.

## Итог первого шага — 9 ноября 2026

Первый запуск завершён. Пользователь выполнил короткий start, Compose сообщил Healthy. Агент установил отдельный маршрут industrial-vision.yaml под общей блокировкой и проверил через TLS loopback и публичный HTTPS: страница, /api/v1/health, /docs и /openapi.json отвечают 200; health возвращает status=ok, Swagger/OpenAPI используют /industrial-vision.

В браузере страница показывает «Сервер отвечает. API доступен.», карточка в pet-каталоге ведёт на /industrial-vision/. Главная oppennec.ru продолжает отвечать HTTPS 200. current указывает на releases/3d5554a55095ebfeadb9360a1ca7f47c9534f0f7, current-docs независим.

Готов только первый шаг: каркас, uv, Docker, страница, API-документация и публикация. БД, авторизация, приём снимков и модель ещё не реализованы. Исходники короткого запуска и последние изменения документации оставлены для коммита пользователю.
